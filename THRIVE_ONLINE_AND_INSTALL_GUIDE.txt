THRIVE — UPDATED WEB APP / MOBILE + PC SETUP
=============================================

FILES
- index.html: updated responsive app with Supabase login, password reset and cloud data syncing.
- manifest.webmanifest + icon-192.png + icon-512.png: installable web app metadata/icons.
- sw.js: service worker for app-shell caching.
- supabase_setup.sql: database table and user-specific security policies.
- This guide.

1) TRY IT LOCALLY
For a quick UI/demo test, open index.html in a browser. Browser local-file mode is only a local demo; PWA install and cloud authentication need a hosted HTTPS site. Do not use local demo mode for sensitive information.

2) PUBLISH THE FILES ONLINE WITH GITHUB PAGES
A. Sign in to GitHub and create a repository (for example, thrive-planner).
B. Upload index.html (rename thrive_personal_growth_planner_updated.html to index.html), manifest.webmanifest, sw.js, icon-192.png and icon-512.png. Keep all files in the repository root together.
C. Open repository Settings -> Pages.
D. Under Build and deployment, select Deploy from a branch, choose main and /(root), then Save.
E. Wait for the published HTTPS URL to appear in Pages settings.
F. If you update the code later, commit/upload the replacement files. GitHub Pages republishes the site.
Official guide: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

3) CREATE A SUPABASE PROJECT FOR REAL ACCOUNTS AND CLOUD SYNC
A. Create a project at https://supabase.com/ and open Project Settings / API.
B. Copy the Project URL and the publishable key (or legacy anon public key).
   NEVER put the service_role key or database password in this HTML.
C. In the Supabase SQL Editor, run all of supabase_setup.sql.
D. In Authentication -> URL Configuration:
   - Set Site URL to the deployed Thrive HTTPS URL.
   - Add that exact deployed URL to the allowed Redirect URLs.
   - Also add the local development URL if you use one.
E. In Authentication -> Providers / Email, enable email sign-up. Configure email delivery for reliable confirmation and password-reset emails. Supabase's default test email service is rate-limited; production apps should configure custom SMTP.
F. Open the deployed Thrive site. On the login page expand “Online setup (Supabase)”, paste Project URL and publishable/anon key, then Save connection.
G. Create an account using an email you can access. Confirm the email if confirmation is enabled, then log in.
H. Make a task or note. Log out, log back in, and check it remains. Then sign in on another device using the same account to verify the cloud sync.

Supabase authentication/password reset docs:
https://supabase.com/docs/guides/auth/passwords
https://supabase.com/docs/reference/javascript/auth-resetpasswordforemail
https://supabase.com/docs/reference/javascript/auth-updateuser
Database row security:
https://supabase.com/docs/guides/database/postgres/row-level-security

4) HOW FORGOT PASSWORD WORKS
- On the hosted site, select “Forgot password?” and enter your account email.
- Supabase emails a recovery link. It must redirect back to your deployed Thrive URL, which must be on Supabase's allowed Redirect URLs list.
- Open the email on the same device/browser where possible. Thrive should show “Choose a new password”; enter a new password and submit.
- If the reset link opens the app but does not show the new-password screen, check the Supabase Redirect URL allowlist, email template and auth logs. Don't share the reset link with anyone.
- Local demo accounts do not have a real forgot-password service. Use Supabase online mode for account recovery.

5) INSTALL IT AS AN APP
Android phone/tablet:
- Open the deployed HTTPS URL in Chrome.
- Open the browser menu (⋮), choose “Install app” or “Add to Home screen”, then confirm.
- Launch Thrive from the home screen like an app.

Windows / macOS / Linux PC:
- Open the deployed HTTPS URL in a supported browser such as Chrome or Edge.
- Use the install icon in the address bar if shown, or browser menu -> Install Thrive / Install page as app.
- The exact label depends on the browser/version.

iPhone/iPad:
- Open the HTTPS site in Safari.
- Tap Share -> Add to Home Screen -> Add.

The PWA can cache the app shell, but authentication, cloud saves, and external lesson links need internet access. Browser support and install prompts vary.

6) IMPORTANT SECURITY AND RELIABILITY NOTES
- This is a practical prototype, not a security-audited production service.
- Cloud mode uses Supabase Auth and a single JSONB row per user. RLS policies in the SQL file restrict each row to its authenticated owner. Test with two separate accounts to ensure isolation.
- The public/publishable key is intended for browser use only when RLS is correctly configured. Never expose a service-role key.
- Do not store highly sensitive health, financial, or identity details in this prototype. Add privacy policy, retention rules, account deletion, backups, rate limits and security review before inviting the public.
- Cloud saves happen asynchronously; keep internet connected and wait briefly after edits before closing. Export backups regularly.
- GitHub Pages serves static files only. Supabase is the separate auth/database service that connects accounts and syncs data between devices.
- Password reset emails can be rate-limited unless email delivery is configured properly.
